# Qwen3.5-9B + RAG в Freedom CQA

В проект добавлен реальный сервис `model_service/service.py`, совместимый с `ModelEvaluator` приложения. Это базовый Qwen3.5-9B в NF4, контекстный поиск E5 + BM25 + BGE reranker и проверка результатов по переданному чек-листу. Веса **не дообучались**. QLoRA исключена по решению пользователя: проверенной обучающей разметки нет.

## Что уже находится в проекте

- `model_service/cqa_runtime.py`: оценка полного исходного транскрипта, RAG, исходные номера доказательств, динамические правила и шкалы, явные ошибки вместо вымышленных оценок.
- `model_service/assets/`: зафиксированные 530 FAQ-фрагментов, E5-эмбеддинги и SHA-256 корпуса. Для проверки продуктовых утверждений используются только найденные материалы; отсутствие ответа в FAQ само по себе не доказывает ошибку оператора.
- `model_service/worker.py`: настоящий загрузчик Qwen, E5 и BGE. GPU 0: Qwen NF4; GPU 1: reranker; E5: CPU. На одном GPU reranker работает на CPU.
- `model_service/attention_t4.py`: экономный SDPA для T4 с сохранением causal/padding mask. Три численных сравнения с исходным attention прошли в Kaggle.
- `model_service/official_checklist.json`: полный официальный чек-лист. Новые установки получают эти правила; уже сохранённые версии чек-листа SQLite не изменены.
- `model_service/audio.py`: отдельный необязательный Voxtral ASR. Он не меняет исходные реплики, номера доказательств или CQA-балл автоматически.
- `tests/test_model_service.py`: контракт сервиса, пользовательские критерии, дробная шкала, исходная нумерация и отказ без подмены демо.

## Запуск настоящей модели

Сервис требует отдельного Python-окружения с CUDA GPU. Текущая NF4-конфигурация проверяется на Kaggle с двумя T4. На этом Mac CUDA недоступна; веб-приложение можно использовать для просмотра результатов, а inference запускать на GPU-хосте. Kaggle notebook не является постоянным API.

На GPU-хосте установите соответствующую CUDA-сборку PyTorch; зафиксированное окружение Kaggle использовало `torch 2.11.0+cu130`. Затем:

```bash
cd /path/to/Freedom/model_service
python -m pip install -r requirements-gpu.txt
export CQA_WEIGHTS_PATH=/path/to/Freedom/models/qwen3.5-9b-nf4
python service.py --port 9000
```

Если `CQA_WEIGHTS_PATH` не задан, loader сначала выбирает локальный `models/qwen3.5-9b-nf4`, если он существует, затем исходный `Qwen/Qwen3.5-9B` из Hugging Face. Это не загрузка дообученного checkpoint. В экспортированном каталоге весов должны быть safetensors shards, index, config с quantization_config, tokenizer и `checkpoint_manifest.json` с хешами каждого файла. Статус загрузки локальных весов и полный round-trip необходимо проверять на CUDA-хосте.

В другом терминале, где запускается приложение Freedom:

```bash
cd /path/to/Freedom
export CQA_MODEL_URL=http://127.0.0.1:9000/evaluate
export CQA_MODEL_NAME='Qwen3.5-9B NF4 + E5/BM25/BGE RAG (base, not fine-tuned)'
export CQA_MODEL_TIMEOUT=900
./start.command
```

`GET http://127.0.0.1:9000/health` показывает готовый сервис и фактический статус базовых весов. Тайм-аут приложения настраивается через `CQA_MODEL_TIMEOUT` (по умолчанию 900 секунд, максимум 3600). При ошибке сервиса приложение сохраняет ошибку; скрытого возврата к DemoEvaluator нет. Пока `CQA_MODEL_URL` не задан, приложение явно остаётся в демо-режиме.

## Контракт и динамический чек-лист

Приложение отправляет `POST /evaluate`:

```json
{
  "conversation": {
    "conversation_id": "new-001",
    "language": "RU",
    "channel": "agent chat",
    "transcript": [
      {"timestamp":"00:00","speaker":"client","text":"Здравствуйте"},
      {"timestamp":"00:05","speaker":"operator","text":"Здравствуйте, я Алина!"}
    ],
    "audio_url": null
  },
  "checklist": [
    {"id":"contact","name":"Установление контакта","weight":10,"type":"binary","na":false,"values":[],"rule":"Оператор поздоровался и представился"}
  ]
}
```

Ответ содержит `criteria`: ровно по одному `{criterion_id,value,rationale,evidence_turns}` на переданный ID. Значение binary/flag — boolean; scale — число из текущей шкалы; null допускается только при `na=true` и выполнении условия неприменимости. `evidence_turns` — номера с 1 по **всем** исходным сообщениям, включая bot/system. Дополнительная metadata помечает ответы как `model_generated_unreviewed`.

Сервис сохраняет текст пользовательского правила. Полные неизменённые официальные правила используют проверки наблюдаемых фактов; новые или изменённые правила оцениваются отдельно по текущему тексту. Для новых продуктовых критериев можно передать `requires_product_evidence=true`. Изменение только веса не требует пересмотра значения; изменение смысла или шкалы требует нового inference. Окончательный балл считает приложение, а не LLM. Грубое нарушение — отдельный флаг, оно не обнуляет результат автоматически.

## Качество и ограничения

На 10 диагностических задачах поиска нужный FAQ в top-3 вырос с 5/10 до 9/10; MRR — с 0.4434 до 0.6833. Это малая диагностическая выборка релевантности RAG, использованная при разработке. Это **не 90% точности CQA**. Для CQA нет независимой полной экспертной разметки; частичные регрессионные проверки не заменяют её. Высокий средний балл оператора также не доказывает качество модели.

Веса не обучались на оценках самой модели. Данные DEV не объявляются обучающими метками. Аудиты и исходные ответы сохраняются отдельно, чтобы специалист мог проверить спорные критерии и апелляции.

Voxtral проверяется как дополнительная расшифровка звонков. Для выбранного 4B checkpoint русский поддерживается, казахский в заявленный языковой набор не входит. Без проверки привязки аудио к репликам нельзя автоматически заменять официальный транскрипт или оценивать эмоции/дикцию по ASR.

Официальная документация: [Qwen3.5-9B](https://huggingface.co/Qwen/Qwen3.5-9B), [Transformers Attention Interface](https://huggingface.co/docs/transformers/attention_interface), [VoxtralRealtime](https://huggingface.co/docs/transformers/model_doc/voxtral_realtime).

Весовые коэффициенты чек-листа, параметры RAG и нейросетевые веса — разные артефакты. Обновление prompt/RAG не означает дообучения Qwen; при таких изменениях обновляются runtime, аудит и release manifest, а точные safetensors остаются прежними. QLoRA не применяется.

## Завершённая веб-интеграция

В приложении добавлен раздел **«Модель и данные»**: URL, имя/режим модели, тайм-аут и проверка `/health`. Если настройки сохранены через UI, SQLite имеет приоритет над переменными окружения. Проверка `/health` подтверждает доступность сервиса; загрузку и оценку нового диалога нужно проверять отдельно. При ошибке inference демо-результат не создаётся.

Импорт оценок с GPU-хоста доступен через **«Диалоги → Импорт оценок»** после загрузки соответствующих транскриптов. Результаты проверяются и маркируются как импортированные. Пакетная обработка имеет сохраняемый прогресс, отмену оставшихся запросов и обработку перезапуска приложения. История сохраняет прошлые оценки и апелляции.

Экспорт DEV/PROD валидирует полноту и структуру, исключает демо и тестовые записи и умеет сохранять официальные локальные `results.json`. Синтетический тестовый HTTP-сервис проверяет соединение фронт/бекенд/контракт, но не является проверкой Qwen или точности CQA. Настоящий GPU-сервис и полный inference должны быть проверены отдельно.


## Отдельная локальная ветка Ollama на Mac

`model_service/ollama_service.py` принимает тот же HTTP-контракт, передаёт полный транскрипт, неизменённые правила и JSON-схему Qwen GGUF через Ollama. В этой ветке FAQ ищется только лексическим BM25; E5/BGE и многошаговый CUDA v42 не используются. Пайплайн `ollama-bm25-v1` маркируется отдельно. Это базовые веса в другой квантизации, без fine-tuning.

Запуск: `./start_model_mac.command`, затем URL приложения `http://127.0.0.1:9000/evaluate`. Артефакты хранятся в `models/ollama`, аудиты в игнорируемом `model_service/inference_audits/ollama`. При ошибке или неполном JSON возвращается ошибка, демонстрационные баллы не подставляются.

Полная конфигурация критериев сравнивается по содержимому, а не по меткам версий разных хостов. При полном совпадении официальных правил Kaggle-v42 и локального чек-листа экспорт доступен; изменение правила, шкалы или веса делает прошлый результат неактуальным до переоценки.

Официальные источники: [Ollama для macOS](https://docs.ollama.com/macos), [GGUF из Hugging Face](https://huggingface.co/docs/hub/en/ollama), [Qwen GGUF](https://huggingface.co/unsloth/Qwen3.5-9B-MTP-GGUF).

## Проверка текущих изменений - 8 ноября 2026

В исходниках CUDA-ветки появился runtime **43.1**: отдельное извлечение наблюдаемых фактов эмпатии с проверкой ролей доказательств, проверка повторного запроса уже названной платформы, совместимость числовых int/float без принятия boolean за число. Загрузчик не задаёт повторную NF4-квантизацию для экспортированного локального checkpoint. Добавлен `refresh_communication.py` для частичного пересмотра коммуникации с сохранением остальных результатов v42; ошибки этапа явно отражаются в manifest, исходный результат сохраняется. Импорт защищает открытые апелляции и уже пересмотренные результаты, а при наличии fingerprints проверяет соответствие транскриптов.

Это **изменения кода и правил, не новые нейросетевые веса**. В этой локальной проверке полный CUDA-прогон 43.1 не выполнялся. Сохранённые 65 результатов DEV остаются v42; работающий на Mac сервис - отдельный `ollama-bm25-v1`. Обновление CUDA-исходников само по себе не переключает Ollama и не пересчитывает DEV.

Проверки новых чистых правил запускаются без Torch/CUDA с явно подставленным ответом экстрактора фактов. Они проверяют логику, типы и номера реплик; качество реального извлечения фактов требует прогона модели и экспертной проверки.
